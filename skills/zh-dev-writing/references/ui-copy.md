# 中文界面文案

## 两种语气，一条分界线

界面文字分两类，语气要求不同：

- **引导类，可以亲切**：页面标题、按钮、空状态、引导说明。短句，直接说事，可以像同事或同学之间说话。「在哪家吃的？」比「请选择餐厅」好。
- **提示类，必须规范**：轻提示、表单校验、拦截面板、确认框、系统消息、加载失败和各种报错。用规范的书面短句，说清**发生了什么**和**下一步怎么做**。

分不清一句话属于哪类时，按提示类写。用户遇到问题时读到口语化的提示，会觉得产品不严肃，甚至不可信。

### 提示类的禁区

- 不用「一下」「吧」「啦」「哦」结尾，不用「开小差」「不太好」「等会儿」「暂时用不了」这类口语。
- 不显示错误码、异常类名、接口路径。
- 不推卸、不卖萌：不写「服务器累了」「哎呀出错了」。

| 不写 | 应写 |
|---|---|
| 用户名设好了，重新登录一下 | 用户名已设置，请重新登录 |
| 人机验证暂时用不了，等会儿再试 | 人机验证暂不可用，请稍后再试 |
| 网络不太好，再试一次 | 网络连接失败，请重试 |
| 请求失败（40001） | 网络连接失败，请重试 |
| 服务器开小差了 | 服务暂不可用，请稍后再试 |
| 操作成功啦！ | 已保存 |

## 按钮与动作

- 按钮写清楚点了会发生什么，用动词或动宾短语：「发布」「加一道菜」「导航去店里」。不写「确定」「好的」，除非对话框的标题已经把动作说清楚了。
- **同一个动作全程只用一个叫法。** 定了「发布」，就不要在别处写成「提交」「上传」「发表」。项目里最好维护一张动作名表。
- 流程里的下一步可以带上对象：「下一步：给袁记云饺加菜」。
- 危险操作的确认框，按钮写出具体动作（「删除这条评论」），不写「确定」；取消按钮写「取消」或「保留」。

## 空状态

- 说清楚现在为什么是空的，以及下一步可以做什么：「还没有收藏的菜，在推荐里点心形就能收藏」。
- 不只写一个「暂无数据」。

## 格式

- 数字和单位之间加一个空格：「320 m」「5 MB」。货币符号紧贴数字：「¥18」，整数不写 .00。
- 时间用相对或口语日期：「12 分钟前」「周一」「10 月 18 日」，不写「2026-10-18 12:03:41」。
- 引用界面里的专名（专题、标签、页面名）用「」：「加了标签「皮薄」」「收进了专题「期末续命餐」」。
- 不用中点「·」把几条信息串成一行，分成两行或用间距隔开。
- 中英文、中文与数字之间是否加空格，跟随项目已有约定；没有约定时加空格。
- 不用 emoji，不用感叹号堆情绪。

## 审查已有文案

- 自己新写的文案直接按本规范写。
- 项目里**已有**的文案不合规时，先列出来问，不自行全部重写：已有文案可能来自设计稿或产品决定，品牌语气的边界也可能另有约定。
